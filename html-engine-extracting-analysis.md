## 1. Введение и постановка задачи

Система статической генерации веб-интерфейса, сформированная в рамках проекта `go-textbook`, доказала свою эксплуатационную надёжность:
* **Нулевой рантайм-оверхед:** 100% Offline First, открытие по протоколу `file:///`, отсутствие бэкенда, Node.js или CDN.
* **Трёхтемная адаптивная дизайн-система:** `paper` (полиграфическая охра), `light` (контрастная светлая), `dark` (глубокая тёмная) с динамическим переключением и anti-flicker инъекцией.
* **Инженерный UI/UX:** Интерактивный drag-to-resize сайдбар с сохранением ширины, TOC с IntersectionObserver-трекингом, прогресс-бар чтения, клавиатурная навигация, ретро-эффекты (VHS, CRT, Phosphor beam), локальный мгновенный поиск без CORS.
* **Инженерный рендеринг:** Автосанитизация и модальный зум/панорамирование схем Mermaid 10.9.1, типографика KaTeX, синтаксическая подсветка Prism, Obsidian Callouts, двусторонние Wikilinks `[[...]]`.
* **Сквозной QA-контроль:** Автоматический аудит кроссплатформенности ФС (Windows/macOS/Linux), битых ссылок, анкоров и headless Firefox-разбор диаграмм Mermaid.

### Цель выделения:
Превратить генератор из встроенного скрипта одного учебника в **автономный репозиторий-основу (`html-textbook-engine`)**, который:
1. Хранит настроенный под персональные предпочтения автора визуальный и функциональный каркас.
2. Легко клонируется/копируется в новые проекты учебников.
3. Полностью отвязан от специфики Go, структуры каталогов `go-textbook` и жестко зашитых текстов.
4. Служит заменой устаревшему 698-КБ процедурному генератору в `go-workout` и базой для `emu-textbook`.

### Почему не Git Submodule / Subtree:
Как справедливо определено в задаче, проекты имеют принципиально разный характер:
* `go-textbook` — классическая фундаментальная лекционная энциклопедия с глубокой иерархией (22 модуля, подразделы, 1413 статей).
* `go-workout` — интерактивный практический задачник на 100 глав и 7 666 упражнений с кластеризацией по 7 образовательным траекториям (Learning Paths), где требуются спойлеры решений, подсказки и валидация кода.
* `emu-textbook` — инженерно-схемотехнический учебник по архитектуре процессоров и ретро-консолей, где требуются диаграммы тактовых сигналов, карты памяти, дампы опкодов, подсветка ассемблеров (6502, Z80, x86) и в перспективе интерактивные Canvas/Wasm-эмуляторы.

Использование `git submodule` привело бы к постоянным конфликтам веток, хрупкости фиксации коммитов и невозможности свободно видоизменять верстку под нужды конкретной книги. Правильная модель — **Starter Engine Template (Репозиторий-шаблон)** с модульным ядром.

## 2. Архитектурный профиль текущего движка (`go-textbook/builder`)

### Состав компонентов и их ответственность:

```
builder/
├── build_all.py        # Оркестратор сборки: CLI, копирование ассетов, сборка CSS, pipeline
├── scanner.py          # Сканирование sources/, модель Article, wikilinks, slugify, TOC
├── converter.py        # Markdown -> HTML, Obsidian callouts, Mermaid sanitization, code blocks
├── template.py         # Каркас HTML5, anti-flicker, sidebar, breadcrumbs, index.html, versioning
├── audit_all.py        # Сквозной QA-аудит (FS Windows compat, broken links, headless Mermaid)
├── verify_editorial.py # Контроль полноты сущностей ДО и ПОСЛЕ авторской редактуры
└── assets/             # Статические ресурсы
    ├── themes/         # manifest.json, paper.css, light.css, dark.css
    ├── style.css       # Базовые CSS-правила и токены компонентов
    ├── main.js         # Vanilla JS (Mermaid zoom, search, sidebar resize, retro effects)
    └── vendor/         # Prism bundle, Mermaid 10.9.1, KaTeX + fonts
```

### Зависимости окружения:
* **Python:** 3.10+ (используется только стандартная библиотека: `os`, `re`, `sys`, `json`, `shutil`, `argparse`, `subprocess` и т.д.).
* **Сторонние Python-пакеты:** ровно **один** — `markdown` (Python-Markdown; расширения `fenced_code`, `tables`, `sane_lists`, `nl2br`).
* **Клиентский стек:** 0 runtime-зависимостей, Vanilla JavaScript, локальные вендорные скрипты.
* **QA-окружение:** Headless Firefox (только для факультативного рантайм-разбора Mermaid в `audit_all.py`).

## 3. Реестр связности (Coupling Audit): Точки проектного хардкода

В ходе глубокого анализа исходного кода `builder/` выявлены 8 критических уровней связности с проектом `go-textbook`, препятствующих немедленному переносу:

### 🔴 Связность 1: Модель файловой структуры источников (`sources/`)
* **Файл:** `builder/scanner.py` (`KnowledgeBaseScanner.scan`)
* **Проблема:** Сканер жестко ожидает каталоги верхнего уровня, отсортированные по регулярному выражению `^(\d+)\.\s*(.*)$`. Внутри модуля он ожидает строго до двух уровней поддиректорий: `root_files`, `subdirs` и `sub_subdirs`.
* **Почему ломается в других проектах:**
  * В `go-workout` исходники лежат **в корне `sources/` плоским списком** из 100 файлов: `1. Пакеты и модули.md` ... `100. Архитектурный Capstone...md`. Папок модулей там нет! При текущем коде `scanner.py` вернет `0 модулей` и `0 статей`.
  * В других учебниках может быть произвольное дерево каталогов (например, `docs/cpu/registers/flags.md` без численных префиксов).
* **Следствие:** Выходные URL жестко конструируются по схеме `docs/{mod_slug}/{sub_slug}/{file_slug}.html`. Невозможно сгенерировать плоские URL (`NNN-slug.html`), как сейчас принято в `go-workout`.

### 🔴 Связность 2: Проектно-специфичные текстовые замены в заголовках
* **Файл:** `builder/scanner.py` (`canonicalize_title`, строки 83–120)
* **Проблема:** В код сканера намертво зашиты правила нормализации для стандартной библиотеки Go:
  ```python
  title = re.sub(r'\bnet_http_httptest\b', 'net/http/httptest', title)
  title = re.sub(r'\bsync_pool\b', 'sync.Pool', title)
  title = re.sub(r'\bgolang_org_x_sys\b', 'golang.org/x/sys', title)
  # ... еще 25 правил для пакетов Go
  ```
* **Почему плохо:** В учебнике по эмуляции или C++ это абсолютно посторонний код, а для произвольного текста — риск неожиданных ложных замен.

### 🔴 Связность 3: Брендинг, логотипы и метаданные портала
* **Файл:** `builder/template.py` (строки 74–81, 442–451, 513–515, 606–626)
* **Проблема:** В шаблоны жестко зашиты:
  * SVG логотип языка Go: `GO_LOGO_SVG` (строка 74).
  * Текст шапки сайдбара: `<span class="logo-title">{GO_LOGO_SVG} BACKEND</span> <span class="logo-sub">Энциклопедия</span>`.
  * Селектор `.logo-go-icon` в `style.css`.
  * Мета-теги: `<title>{title} | Инженерная энциклопедия бэкенда</title>`, мета-описание про Go.
  * Тексты футера: `Инженерная веб-энциклопедия бэкенда и языка Go • Авторский стиль Брайана Кернигана`.

### 🔴 Связность 4: Структура и контент главной страницы (`index.html`)
* **Файл:** `builder/template.py` (`render_index_page`, строки 558–725)
* **Проблема:** Функция `render_index_page` не является универсальной:
  * Жесткий заголовок: «Фундаментальный бэкенд на Go: от кремния до распределенных систем».
  * Цитата Кернигана: «Управление сложностью — вот суть программирования».
  * Хардкод статистики: блок `<span class="stat-number">22</span> <span class="stat-desc">Тематических модуля</span>`.
  * Хардкод секции дорожной карты (`learning-roadmap`): 4 шага (Кремний и ОС, Глубокий Go, Хранилища, Надежность).
* **Следствие:** При сборке любого другого учебника главная страница отображает совершенно нерелевантный контент `go-textbook`.

### 🔴 Связность 5: Ключи `localStorage` в клиентском коде
* **Файлы:** `builder/template.py` (`make_anti_flicker_script`), `builder/assets/main.js` (строки 161, 850, 917)
* **Проблема:** Для хранения настроек используются жестко прописанные константы:
  * `go_encyclopedia_theme`
  * `go_encyclopedia_sidebar_width`
  * `go_encyclopedia_retro_effects_{theme}`
* **Опасность:** Если пользователь открывает несколько учебников автора на одном локальном сервере (например, `localhost:8080`, `localhost:3000`) или в одном домене GitHub Pages (`user.github.io/go-textbook` и `user.github.io/go-workout`), настройки тем, ширина сайдбара и ретро-эффекты будут перезаписывать друг друга и конфликтовать.

### 🔴 Связность 6: Захардкоженные подсказки поиска
* **Файлы:** `builder/template.py` (строка 632), `builder/assets/main.js` (строка 535)
* **Проблема:**
  * Плейсхолдер инпута: `placeholder="Поиск по 1 413 лекциям (например: netpoller, GC, MVCC, Raft, CAS)..."`
  * JS empty state: `dropdown.innerHTML = 'Ничего не найдено. Попробуйте другой запрос (например: GC, Raft, epoll, каналы).'"`
* **Следствие:** В задачнике или учебнике по эмуляторам эти примеры выглядят некорректно.

### 🔴 Связность 7: Ограниченный набор Obsidian Callouts
* **Файл:** `builder/converter.py` (`CALLOUT_CONFIG`, строки 14–63)
* **Проблема:** Спецификация блоков callout заточена под теорию и интервью:
  * `tip`: "Совет / Собеседование"
  * `interview`: "Вопрос с собеседования"
  * `info`: "Под капотом (Mechanical Sympathy)"
  * `warning`: "Подводные камни / Gotcha"
* **Чего не хватает для задачника (`go-workout`):**
  * `[!task]` / `[!exercise]` — формулировка практической задачи.
  * `[!solution]` — эталонное решение (желательно с поддержкой `<details>`/сворачивания).
  * `[!hint]` — подсказка.
  * `[!test]` — тест-кейсы и проверки.
* **Чего не хватает для эмуляции (`emu-textbook`):**
  * `[!hardware]` / `[!chip]` — спецификация микросхемы/регистров.
  * `[!timing]` — диаграммы тактов и циклов инструкции.
  * `[!memory]` — карта адресов и зеркалирование памяти.

### 🔴 Связность 8: Механизм получения версии проекта
* **Файл:** `builder/template.py` (`get_project_version`, строки 14–56)
* **Проблема:** Функция ищет строго файл `../AGENTS.md` и парсит конкретную строку `**Current project version:** x.y.z`. Если файла нет или формат отличается, сборщик падает с исключением `[VERSION ERROR]`.

### 4.3. Рефакторинг ключевых модулей

#### 1. `engine/scanner.py` (Универсальный сканер контента)
* **Поддержка трех режимов сканирования:**
  1. `nested` (как в `go-textbook`): модули-папки -> подпапки -> статьи с неограниченной глубиной (рекурсивный обход дерева).
  2. `flat` (как в `go-workout`): сканирование файлов прямо в корне `sources/` с группировкой по виртуальным модулям (кластерам/траекториям) или единым списком.
  3. `auto`: если в `sources/` обнаружены директории — переключается в `nested`, если только `.md` файлы — во `flat`.
* **Поддержка Frontmatter:**
  Если статья начинается с YAML-блока (`---`), метаданные (`title`, `order`, `track`, `difficulty`, `tags`) читаются оттуда, с fallback на H1 и имя файла.
* **Генерация выходных путей:**
  Режим `url_style`: `"nested"` (`docs/01-mod/art.html`) или `"flat"` (`NNN-art.html` или `art.html`).

#### 2. `engine/converter.py` (Расширяемый процессинг Markdown)
* **Реестр Callouts через конфиг:**
  Базовые типы (`note`, `warning`, `tip`, `important`, `danger`, `caution`, `info`) объявляются по умолчанию. Дополнительные (`task`, `solution`, `hint`, `hardware`, `register`) передаются из конфигурации.
* **Поддержка сворачиваемых блоков (Collapsible Callouts):**
  Возможность рендеринга `<details class="callout callout-solution">` для скрытия решений упражнений до клика читателя.
* **Изоляция Mermaid:**
  Выделение санитизации и парсинга Mermaid в чистый класс/плагин `MermaidProcessor`.

#### 3. `engine/template.py` (Параметрический генератор страниц)
* **Устранение хардкода:**
  Все названия, логотипы, фавиконки, копирайты и тексты берутся из объекта `Config`.
* **Префикс изоляции хранилища:**
  В тег `<html>` инжектируется атрибут `data-storage-prefix="{config.storage_prefix}"`. Скрипты читают его, гарантируя полную изоляцию `localStorage` между разными книгами.
* **Модульная главная страница:**
  Поддержка разных типов главной страницы:
  - `catalog` — сетка модулей/глав с поиском и статистикой (дашборд).
  - `article` — главная страница собирается из `sources/index.md` или `sources/README.md`.
  - `custom` — подключение кастомного шаблона `templates/index.html`.

#### 4. `engine/assets/main.js` (Клиентский декаплинг)
* Чтение ключей хранилища через префикс:
  ```javascript
  const prefix = document.documentElement.dataset.storagePrefix || 'textbook_engine';
  const THEME_KEY = `${prefix}_theme`;
  const SIDEBAR_KEY = `${prefix}_sidebar_width`;
  const RETRO_KEY = `${prefix}_retro_effects`;
  ```
* Чтение поисковых текстов и подсказок из `dataset` элементов интерфейса вместо зашитых констант.

#### 5. `engine/audit.py` (Универсальный QA-аудитор)
* Запуск без завязки на текущую директорию:
  `python engine/audit.py --dist ./dist --repo-root .`
* Аудит адаптируется к плоской или вложенной структуре страниц.

### Модель интеграции в проекты учебников:

```
[html-textbook-engine] (Template Repo на GitHub / локальная база)
         │
         ├───► Скопировать папку engine/ в go-workout/builder/ (или engine/)
         │     Настроить go-workout/book.config.json
         │     Кастомизировать под задачи (exercise callouts, 7 tracks)

         └───► Скопировать папку engine/ в emu-textbook/engine/
```

**Преимущества подхода:**
1. **Полная независимость:** Никаких `git submodule update`, отвязанных HEAD, проблем с правами доступа или блокировок версий.
2. **Свобода кастомизации:** В `go-workout` можно без оглядки на другие проекты дописать генератор тестов, а в `emu-textbook` — подключить Canvas-эмулятор.
3. **Единый визуальный стандарт:** Все учебники сохраняют фамильный стиль: Кернигановскую ясность, трехтемную палитру, удобный сайдбар, ретро-эффекты и высочайшую скорость работы.

## 9. Резюме

Система генерации из `go-textbook` представляет собой зрелый, технически выверенный продукт с редким сочетанием нулевых сетевых зависимостей, высокой производительности и качественного интерфейса. 

Выделение её в отдельный репозиторий-шаблон `html-textbook-engine` потребует минимального хирургического вмешательства:
* **Не нужно переписывать CSS и дизайн-систему:** стили и темы уже идеально модульны.
* **Не нужно менять алгоритмы верстки и Mermaid:** они тщательно отлажены и стабильны.
* **Главное действие:** параметризовать модель сканирования источников (поддержать плоский список файлов для задачника) и вынести брендинг с текстами в декларативный конфиг `book.config.json`.

Этот шаг полностью решит текущую проблему сборки в `go-workout`, создаст прочный фундамент для `emu-textbook` и позволит в считанные минуты разворачивать новые веб-учебники авторского уровня.
