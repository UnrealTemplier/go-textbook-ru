### Раунд 1: Критика №1 — Технический аудит и выявление критических угроз (Claude Opus)
* **Документ:** [`html-engine-extracting-analysis-critics-1.md`](file:///home/ut/work/go-textbook/html-engine-extracting-analysis-critics-1.md)
* **Ключевые находки и критика:**
  - **🔴 F1 (Катастрофическая ошибка данных):** В `sources/*.md` `go-workout` лежат только краткие формулировки задач (2.8 МБ). Вся теория, алгоритмы, 13 946 блоков кода и разборы лежат в 41 МБ `chapter*_data.json` и `gen_ch*.py`. Буквальное удаление JSON уничтожает весь учебник!
  - **🔴 F2 (Поломка URL):** В `go-workout` своя транслитерация (длина неограничена, префикс `{num:03d}-`). Функция `slugify(..., 55)` меняет 20 из 100 URL.
  - **🔴 F3 (Несуществующие фичи):** Проведена ревизия кода `main.js`; опровергнуты TOC IntersectionObserver, панорамирование Mermaid, двусторонние wikilinks.
  - **🟠 F4–F6 (Качество и дефекты):** Вскрыты 355 мертвых wikilinks в `dist/`; показан дефект `color` в Callouts; указана неточность примеров `localStorage`.
  - **🟡 F7–F9 (Архитектура стека):** Предложено отказаться от Jinja2/Pydantic в пользу стандартного `tomllib` (Python 3.11+) и `dataclasses`. Указано на отсутствие тестов и рецепта сборки бандла Prism.
  - **Архитектурные требования A1–A10:**
    - `go-textbook` обязан стать Потребителем №0: критерий Фазы 1 — пустой `diff -r dist/`.
    - Сайдбар занимает 84% веса (304 КБ из 360 КБ) и раздувает `dist/` до 506 МБ: предложен переход на динамический сайдбар через `nav-data.js`.
    - Вместо чистого копирования шаблона предложен `git subtree` или скрипт синхронизации ядра.

### Раунд 2: Ответ/Критика №2 — Архитектурный синтез и встречный аудит (Gemini)
* **Документ:** [`html-engine-extracting-analysis-critics-2.md`](file:///home/ut/work/go-textbook/html-engine-extracting-analysis-critics-2.md)
* **Что было признано и исправлено:**
  - Безоговорочно приняты ошибки F1, F2, F3, замечания по стеку (отказ от Pydantic/Jinja2 в пользу `book.toml`).
  - Утвержден статус `go-textbook` как Потребителя №0 со строгим оракулом `diff -r dist/ == 0`.
* **Встречные аргументы и контрпредложения:**
  - **С1 (Риск монолитной конвертации):** Сливать главу на 91 задачу в единый файл Markdown опасно (деградация парсера, проблемы отступов кода в цитатах). Предложена иерархическая модель A2 (папка главы + файлы разделов).
  - **С2 (Токсичность `git subtree`):** `git subtree` провоцирует конфликты при работе AI-агентов. Предложен безопасный двухуровневый вендоринг ядра с утилитой контроля хешей `python -m engine.sync`.
  - **С3 (Опасность чистого JS-сайдбара):** Чистый JS-сайдбар ломает SEO и Offline-First при отключенном JS. Спроектирована **Архитектура Гибридного Сайдбара (Hybrid Sidebar)**: активный модуль рендерится в статический HTML (~6–29 КБ), а остальные модули гидрируются из `nav-data.js`.
  - **С4 (Семантический верификатор `verify_diff.py`):** Слепой `diff -r` не годится для фазы намеренных оптимизаций (дедупликация ID, гибридный сайдбар). Нужен нормализатор для проверки неприкосновенности тела статей.
  - **Расследование структуры `go-workout`:** Выявлено, что 100 глав покрываются 22 блоками, а 7 Learning Paths являются карьерными оверлеями.

### Раунд 3: Критика №3 — Директивы пользователя U1–U10 и разделение задач (Claude Opus)
* **Документ:** [`html-engine-extracting-analysis-critics-3.md`](file:///home/ut/work/go-textbook/html-engine-extracting-analysis-critics-3.md)

  - **Р1 (Баг в пре-токенизаторе):** Замена `%%CODEBLOCK%%` регуляркой ломает код внутри выносок (754 строки в 272 статьях) и Mermaid. Необходим построчный парсер оград с переносом на Этап 3.

  - **Р6 (Отказ от режима `flat`):** Поскольку задача — это файл, а глава — папка, `go-workout` стал вложенным. Режим `flat` исключается по YAGNI.
  - **Спецификация Задачи Б:** Формат страницы задачи с разделами `##`, имя файла «номер + короткое имя», заголовок из H1 (`title_source = "h1"`), разделители KaTeX `\(...\)` для изоляции от переменных `$GOPATH`.

  - **Фактологическое расследование по сломанному коду:** Найдено ровно **7 страниц** (а не 5), где `[[...]]` ломает fenced-код (YAML `arguments`, LeetCode тесты, Go-комментарии).
  - **Развенчание мифа об «активных ссылках в inline-коде»:** Проверено по `dist/`: 53 страницы УЖЕ рендерят экранированный видимый мусор `<code>&lt;a href...&gt;</code>` и ссылки не кликабельны. Полноценная защита fenced-кода построчным автоматом перенесена на Этап А3а.
  - **Формат задачи `##` утвержден:** Гарантирует появление интерактивного TOC в правом сайдбаре (при выносках TOC был бы пуст).

  - **Унификация глав 1–100:** Рекомендовано не плодить папки разделов для глав 1–22, а сделать структуру всех 100 глав единообразной (глава -> задачи).
  - **Полный консенсус:** Нулевой остаток разногласий.

## 5. Целевое состояние архитектуры (Consensus Baseline)

### 5.1. Задача А: Автономное ядро `html-textbook-engine`

```text
html-textbook-engine/
├── engine/                      # НЕПРИКОСНОВЕННОЕ ЯДРО (Upstream Core)
│   ├── __init__.py
│   ├── build.py                # Главный CLI: python -m engine.build [--all, --module, --clean]
│   ├── config.py               # Загрузка и валидация book.toml (tomllib + dataclasses)
│   ├── scanner.py              # Рекурсивный обход дерева каталогов произвольной глубины
│   ├── converter.py            # Markdown -> HTML, Obsidian Callouts, Mermaid, KaTeX
│   ├── template.py             # Каркас HTML5, Гибридный сайдбар, Breadcrumbs, TOC
│   ├── audit.py                # Сквозной QA: FS Windows, 0 CDN, Links, Anchors, Mermaid
│   ├── sync.py                 # CLI обновления ядра: python -m engine.sync
│   ├── VERSION                 # SemVer версия движка (например, 1.2.0)
│   ├── .checksums.json         # SHA-256 контрольные суммы файлов ядра
│   ├── strings/
│   │   └── ru.toml             # Базовый словарь локализации UI (150+ строк)
```
