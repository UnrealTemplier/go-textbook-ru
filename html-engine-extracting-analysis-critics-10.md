### 2.1. Вопрос 1 (В21): Граничные случаи `IndentedFenceExtension`, ловушка длины ограды и конечный автомат

> **Вопрос рецензента:** *Согласны ли ограничить блок `IndentedFenceExtension` (пустой код, первая закрывающая ограда того же или меньшего отступа, отказ при строке с меньшим отступом), перенести его на приоритет 24, а препроцессор списков — на 23 (В21)?*

**Ответ: ДА, В ЦЕЛОМ СОГЛАСЕН С ПРИНЦИПОМ, НО С ВАЖНЫМ КРИТИЧЕСКИМ УТОЧНЕНИЕМ.**

#### Вскрытая скрытая ловушка в формулировке рецензента:
Рецензент пишет:
> *«Закрывающей оградой считается первая строка с ``` / ~~~ того же или меньшего отступа».*

Если реализовать это правило буквально, возникает тяжелая синтаксическая регрессия:
1. **Несовпадение символа ограды:** Если блок открыт обратными кавычками ```` ``` ````, строка `~~~` внутри кода (или с отступом) **не имеет права** закрывать этот блок. В CommonMark и Python-Markdown символ закрывающей ограды обязан строго совпадать с символом открывающей ограды (`fence_char`).
2. **Длина ограды ($L_{close} < L_{open}$):** Если блок открыт 4 кавычками ```` ```` ```` (например, демонстрация Markdown-разметки), вложенная ограда из 3 кавычек ```` ``` ```` **не имеет права** закрывать внешний блок! Закрывающая ограда обязана иметь длину **не меньше** длины открывающей ограды ($L_{close} \ge L_{open}$). Иначе любой пример кода со вложенными блоками превратится в сломанный огрызок.
3. **Разница между отступом строки и синтаксисом ограды:** Меньший или равный отступ допускается **только для позиции самой ограды** (например, открывающая с отступом в 3 пробела, закрывающая — с 2 пробелами, как допускает Obsidian). Но сам маркер ограды должен строго соответствовать правилам Markdown.

#### Почему регулярное выражение здесь неприменимо:
Попытка выразить все 8 граничных случаев единым регулярным выражением порождает громоздкого монстра, склонного к катастрофическому бэктрекингу и сбоям на пустых блоках (что и произошло в Ответе №8 с `[\s\S]*?\n`).

#### Эталонное решение — построчный конечный автомат:
Вместо регулярки препроцессор `IndentedFencePreprocessor` реализуется как детерминированный построчный конечный автомат внутри метода `run(lines: list[str]) -> list[str]`:
1. **Приоритет 24:**
   - Библиотечный `fenced_code` отрабатывает на приоритете **25** и убирает все внешние блоки нулевого отступа в `htmlStash`.
   - `IndentedFencePreprocessor` на приоритете **24** гарантированно работает только с оградами с отступом и никогда не затронет блоки верхнего уровня или примеры кода внутри них (Случай 3 снят).
   - `ListBlockPreprocessor` работает на приоритете **23**: к моменту его запуска весь вложенный код (включая спископодобные строки YAML `- name: test` или Go-комментарии `// - item`) уже надежно упакован в плейсхолдеры `htmlStash` и невидим для логики нормализации списков.
2. **Логика автомата:**
   - Состояние `OUTSIDE`: сканируем строки. Если строка начинается с `indent` (1–3 пробела, либо отступ элемента списка), за которым следует маркер `fence` (минимум 3 символа `` ` `` или `~`):
     - Если блок имеет отступ $\ge 4$ пробела и находится **вне** контекста списка — он игнорируется (согласно CommonMark это стандартный 4-пробельный блок кода, Случай 4).
     - Иначе фиксируем `open_indent`, `fence_char`, `fence_len`, `lang = line[indent_len + fence_len:].strip()`. Переходим в состояние `INSIDE`.
   - Состояние `INSIDE`:
     - Строка является пустой: добавляется в буфер кода как `\n` (пустые строки внутри блока валидны).
     - Непустая строка имеет отступ меньше `open_indent`, и при этом **не является валидной закрывающей оградой**: это означает синтаксический обрыв блока! Автомат сбрасывает накопленный буфер как обычные строки текста, логирует предупреждение и возвращается в `OUTSIDE` (Случаи 1 и 2 решены без захвата чужого текста).
     - Строка имеет маркер `close_fence` из тех же символов `fence_char`, длиной $\ge fence\_len$, с отступом $\le open\_indent$: найден конец блока!
     - Из всех строк кода снимается базовый отступ `open_indent` (но не более того, чтобы сохранить внутреннее форматирование кода).
     - Блок экранируется через канонический `_escape` (как в `fenced_code`, сохраняя апострофы `'`, Случай 8).
     - Генерируется HTML `<pre><code class="language-{lang}">{code}</code></pre>` (или без класса, если языка нет, Случай 7).
     - Сохраняется в `self.md.htmlStash.store(code_html)`.
     - В результирующий список строк помещается `{open_indent}{placeholder}` (без лишних пустых строк, сохраняя принадлежность к элементу списка, Случай 5).

Все 8 сценариев синтетики (§ 6.2 Критики №9) покрываются этим автоматом со 100% точностью и включаются в `test_indented_fence.py`. Полный код компонента приведен в [§ 4.1](#41-автомат-оград-indentedfencepreprocessor-построчный-сканер-приоритет-24).

### 2.2. Вопрос 2 (В22): Построчная маска кода `CodeSpanIndex`, изоляция выносок и инвариант строк

> **Вопрос рецензента:** *Согласны ли строить маску кода по строкам по выходу того же конвейера препроцессоров, отдельно для статьи и каждой выноски, включая ограды с отступом после А3з (В22)?*

**Ответ: ДА, ПОЛНОСТЬЮ СОГЛАСЕН.**

#### Почему предложение рецензента математически безупречно:
Рецензент вскрыл ключевое расхождение: в Ответе №8 `CodeSpanIndex` работал по сырой строке, тогда как библиотечный `NormalizeWhitespace` (приоритет 30) модифицирует текст до обработки оград:
- раскрывает символы табуляции `expandtabs(tab_length)`;
- преобразует CRLF (`\r\n`) и CR (`\r`) в LF (`\n`);
- удаляет служебные управляющие символы STX (`\x02`) и ETX (`\x03`).

Раскрытие TAB меняет посимвольные смещения (character offsets), из-за чего символьные спаны `(start, end)` из сырого текста могут разъезжаться с реальной разметкой.

#### Доказательство строчного инварианта:
Хотя посимвольные позиции сдвигаются при `expandtabs`, **номера строк остаются строго инвариантными**:
1. Раскрытие `\t` в пробелы не меняет количество символов перевода строки `\n`.
2. Замена `\r\n` на `\n` сохраняет то же самое количество строк.
3. Одиночные символы `\r` запрещены новым правилом аудита (В19 / U18) и отсутствуют в репозитории.
4. Символы STX/ETX не содержат переносов строк.

Следовательно, номер строки $L$ в нормализованном тексте препроцессоров **строго равен номеру строки $L$ в исходном тексте статьи**.

#### Архитектура строчной маски `CodeSpanIndex`:
1. Текст пропускается через `NormalizeWhitespace` библиотеки Python-Markdown.
2. По тексту прогоняются детекторы оград:
   - Библиотечный `FencedBlockPreprocessor.FENCED_BLOCK_RE` (ограды нулевого отступа).
   - Наш `IndentedFencePreprocessor` (ограды с отступом, после коммита А3з).
3. Формируется множество номеров строк `fenced_code_lines: Set[int]`, входящих в диапазоны `[line_start, line_end]`.
4. Для сопоставления строковых позиций в сыром тексте с номерами строк строится массив смещений начал строк `line_starts = [0, ...]`. Для любого смещения `pos` номер строки вычисляется за $O(\log N)$ через `bisect_right(line_starts, pos)`.
5. **Выноски Obsidian (`[!NOTE]`):** Тело выноски парсится как независимый изолированный Markdown-документ (`inner_md`). Для каждого тела выноски строится своя локальная маска строк `CodeSpanIndex(inner_md)`. Это гарантирует, что рекурсивная обработка викиссылок в выносках (коммит А3а′) не имеет слепых зон.
6. **Четкое разделение зон ответственности:**
   - `CodeSpanIndex` маскирует **блочный fenced-код** (запрет обработки клише и викиссылок U10).
   - Инлайн-код (обратные кавычки `` `...` ``) регулируется правилами U11 и U20: если `[[...]]` находится внутри бэктиков, викиссылка создается только при наличии целевой статьи в графе знаний; массивы LeetCode `[[0,0]]` и неопределенные сущности остаются буквальным текстом.

### 2.3. Вопрос 3 (В23): Архитектура рантайма `window.__BOOK__`, гигиена ассетов и аудит URL

> **Вопрос рецензента:** *Согласны ли дополнить `window.__BOOK__`: ключ ширины сайдбара, `THEME_KEY`, защита от отсутствия объекта, `?v=` у ассетов, сравнение множеств в тесте (В23)?*

Все 5 предложений рецензента абсолютно оправданы и закрывают практические риски:

1. **Ключ ширины сайдбара:**  
   В `main.js:161` хардкод `STORAGE_KEY = 'go_encyclopedia_sidebar_width'` заменяется на `B.storageKey("sidebar_width")`. Для `go-textbook` это дает `'go_encyclopedia_sidebar_width'`, а для `go-workout` — `'go_workout_sidebar_width'`, полностью исключая межпроектные коллизии на общем origin GitHub Pages.
2. **Ключ переключения темы:**  
   В `main.js:850, 894` хардкод `THEME_KEY = 'go_encyclopedia_theme'` заменяется на `B.storageKey("theme")`.
3. **Защитный Guard от рассинхронизации:**  
   В начале `main.js` объявляется безопасный fallback:
   ```javascript
   const B = window.__BOOK__ || {
     storageKey: function(k) { return 'go_encyclopedia_' + k; },
     readRetro: function() { return null; },
     applyRetro: function() {},
     getTheme: function() { return document.documentElement.dataset.theme || 'dark'; },
     applyTheme: function(t) { document.documentElement.dataset.theme = t; }
   };
   if (!window.__BOOK__) {
     console.warn('[Engine] window.__BOOK__ is not defined. Using safe fallback.');
   }
   ```
   Это полностью предотвращает выброс исключений `TypeError` при частичной сборке (`--module N`) или при кэшировании старого HTML браузером.
4. **Кэш-бастинг ассетов `?v=<version>` и аудит:**  
   В `template.py` пути к стилям и скриптам дополняются версией:  
   `<link rel="stylesheet" href="{rel_root}assets/style.css?v={version}">`  
   `<script src="{rel_root}assets/main.js?v={version}"></script>`  
   *Важное инженерное дополнение:* В `builder/audit_all.py` (и целевом `engine/audit.py`) проверка существования локальных файлов по протоколу `file:///` обязана нормализовать URL и отсекать query-параметры (`href.split("?", 1)[0]`), иначе `os.path.exists()` на файловой системе вернет `False`, ошибочно посчитав ассет с `?v=1.1.0` битой ссылкой.
5. **Валидация префикса:**  
   В `config.py` значение `storage_prefix` строго проверяется регулярным выражением `^[a-z0-9_]+$`, исключая любые риски синтаксических инъекций в инлайн-скрипт `<head>`.
6. **Сравнение словарей в `test_runtime.py`:**  
   Интеграционный тест в headless Firefox нормализует `style.cssText` в словарь `{property: value}` и сравнивает атрибуты DOM как множества/словари, игнорируя незначимый порядок сериализации свойств браузерным движком.

### 3.1. Н8 / U24: Разметка в заголовках H2–H4 и архитектура `HeadingTreeprocessor`

Вскрытый рецензентом дефект Н8 — серьезная недоработка исторического пайплайна. Метод `_process_headings` в `converter.py` заменял строку `## Заголовок` на сырой HTML `<h2 id="...">Заголовок</h2>` **до** запуска Python-Markdown. 2. **Парсинг Markdown:** Библиотека Python-Markdown штатно транслирует inline-разметку заголовка: бэктики становятся `<code>testing.B</code>`, а `<pid>` корректно экранируется в `&lt;pid&gt;`.

   - Гарантирует 100% совпадение `id` в HTML с анкорами в TOC и правым сайдбаром.
   - Не затрагивает заголовки внутри выносок (поскольку выноски парсятся в изолированных вызовах `md.convert`).
   - 119 заголовков с формулами KaTeX остаются неизменными.

## 4. Эталонный production-ready код обновленных компонентов ядра

Ниже представлены полностью переработанные реализации компонентов, устраняющие все 8 дефектов синтетики и закрывающие вопросы В20–В24.

### 4.1. Автомат оград `IndentedFencePreprocessor` (построчный сканер, приоритет 24)

```python
"""
engine/converter/indented_fence.py
Построчный конечный автомат для обработки блоков кода с отступом внутри элементов списков.
Приоритет: 24 (после fenced_code=25, до list_preprocessor=23).
"""

import re
import markdown
from markdown.preprocessors import Preprocessor

class IndentedFencePreprocessor(Preprocessor):
    # Распознавание открывающей ограды: 1-3 пробела (или отступ списка), минимум 3 кавычки или тильды
    OPEN_FENCE_RE = re.compile(r'^(?P<indent>[ \t]+)(?P<fence>`{3,}|~{3,})[ ]*(?:\.?(?P<lang>[\w#.+-]*))?[ ]*$')

    def run(self, lines: list[str]) -> list[str]:
        new_lines: list[str] = []
        i = 0
        n = len(lines)

        while i < n:
            line = lines[i]
            m = self.OPEN_FENCE_RE.match(line)
            
            # Проверяем потенциальное начало блока с отступом
            if m:
                open_indent = m.group('indent')
                fence_str = m.group('fence')
                fence_char = fence_str[0]
                fence_len = len(fence_str)
                lang = m.group('lang') or ''
                indent_len = len(open_indent)

                # Правило CommonMark: отступ >= 4 пробела вне списков считается стандартным кодом
                if indent_len >= 4 and not self._is_inside_list_context(lines, i):
                    new_lines.append(line)
                    i += 1
                    continue

                # Ищем закрывающую ограду и собираем строки кода
                code_lines: list[str] = []
                j = i + 1
                closed = False

                while j < n:
                    cur_line = lines[j]
                    stripped = cur_line.strip()

                    # Проверка на закрывающую ограду:
                    # Тот же символ, длина >= открывающей, отступ <= открывающего
                    if stripped.startswith(fence_char * fence_len):
                        close_match = re.match(r'^(?P<indent>[ \t]*)(?P<fence>`{3,}|~{3,})[ ]*$', cur_line)
                        if close_match:
                            c_indent = close_match.group('indent')
                            c_fence = close_match.group('fence')
                            if c_fence[0] == fence_char and len(c_fence) >= fence_len and len(c_indent) <= indent_len:
                                closed = True
                                break

                    # Проверка на обрыв блока: непустая строка с отступом МЕНЬШЕ базового
                    cur_indent_len = len(cur_line) - len(cur_line.lstrip(' '))
                    if stripped and cur_indent_len < indent_len:
                        # Обрыв синтаксиса: строка не принадлежит блоку!
                        closed = False
                        break

                    code_lines.append(cur_line)
                    j += 1

                if closed:
                    # Блок успешно распознан. Снимаем общий базовый отступ
                    clean_code_lines = []
                    for c_line in code_lines:
                        if c_line.startswith(open_indent):
                            clean_code_lines.append(c_line[indent_len:])
                        elif not c_line.strip():
                            clean_code_lines.append('')
                        else:
                            clean_code_lines.append(c_line.lstrip(' '))

                    raw_code = "\n".join(clean_code_lines)
                    escaped_code = self._escape_code(raw_code)

                    lang_attr = f' class="language-{lang}"' if lang else ''
                    html_code = f'<pre><code{lang_attr}>{escaped_code}</code></pre>'
                    placeholder = self.md.htmlStash.store(html_code)

                    # Сохраняем исходный отступ пункта списка!
                    new_lines.append(f"{open_indent}{placeholder}")
                    i = j + 1
                    continue

            new_lines.append(line)
            i += 1

        return new_lines

    def _is_inside_list_context(self, lines: list[str], idx: int) -> bool:
        """Проверяет, предшествует ли строке пункт списка."""
        for k in range(idx - 1, max(-1, idx - 6), -1):
            prev = lines[k].strip()
            if not prev:
                continue
            if re.match(r'^(?:[-*+]|\d+\.)\s+', prev):
                return True
            break
        return False

    def _escape_code(self, txt: str) -> str:
        """Экранирование в точном соответствии с fenced_code (сохраняет апострофы)."""
        return txt.replace('&', '&amp;').replace('<', '&lt;').replace('>', '&gt;').replace('"', '&quot;')

class IndentedFenceExtension(markdown.Extension):
    def extendMarkdown(self, md: markdown.Markdown):
        md.preprocessors.register(IndentedFencePreprocessor(md), "indented_fence", 24)
```

### 4.2. Построчная маска кода `CodeSpanIndex` с поддержкой выносок

```python
"""
engine/converter/code_mask.py
Построчный индекс блоков кода для защиты от искажения клише и викиссылками.
"""

from bisect import bisect_right
import markdown
from markdown.extensions.fenced_code import FencedBlockPreprocessor

class CodeSpanIndex:
    def __init__(self, raw_text: str, md_instance: markdown.Markdown):
        self.raw_text = raw_text
        self.line_starts: list[int] = []
        self._build_line_starts(raw_text)

        # 1. Нормализация текста через штатный NormalizeWhitespace
        normalized_text = md_instance.preprocessors['normalize_whitespace'].run(raw_text.split('\n'))
        norm_str = '\n'.join(normalized_text)

        # 2. Сбор строк, занятых блоками кода
        self.fenced_lines: set[int] = set()
        self._collect_fenced_blocks(norm_str)

    def _build_line_starts(self, text: str):
        pos = 0
        self.line_starts = [0]
        for line in text.splitlines(keepends=True):
            pos += len(line)
            self.line_starts.append(pos)

    def _collect_fenced_blocks(self, text: str):
        # Поиск по каноническому FENCED_BLOCK_RE
        for m in FencedBlockPreprocessor.FENCED_BLOCK_RE.finditer(text):
            start_pos, end_pos = m.span()
            start_line = bisect_right(self.line_starts, start_pos)
            end_line = bisect_right(self.line_starts, end_pos)
            for l in range(start_line, end_line + 1):
                self.fenced_lines.add(l)

    def is_line_in_code(self, char_offset: int) -> bool:
        """Проверяет, принадлежит ли символ строке, входящей в блок кода."""
        line_num = bisect_right(self.line_starts, char_offset)
        return line_num in self.fenced_lines
```

"""
engine/converter/headings.py
Обработка заголовков H2-H4: разметка рендерится Markdown, ID выставляются Treeprocessor.
"""

import xml.etree.ElementTree as etree
import markdown
from markdown.treeprocessors import Treeprocessor

class HeadingTreeprocessor(Treeprocessor):
    def __init__(self, md: markdown.Markdown, slugs_provider):
        super().__init__(md)
        self.slugs_provider = slugs_provider

    def run(self, root: etree.Element):
        slugs = self.slugs_provider()
        idx = 0
        # Обходим дерево в поисках H2..H4
        for elem in root.iter():
            if elem.tag in ('h2', 'h3', 'h4'):
                if idx < len(slugs):
                    elem.attrib['id'] = slugs[idx]
                    idx += 1

class HeadingExtension(markdown.Extension):
    def __init__(self, slugs_provider):
        self.slugs_provider = slugs_provider

    def extendMarkdown(self, md: markdown.Markdown):
        md.treeprocessors.register(HeadingTreeprocessor(md, self.slugs_provider), "heading_id", 5)
