## 3. Q1 (U18): восстановление LaTeX в `sources/`

**Ответ: да, отдельным коммитом и строго до А0.** Поправки к § 3.5 ответа — ниже (В19).

3. **Оракул А1–А2.** `diff -r dist/` нужно сравнивать с `dist/`, собранным по исправленным исходникам.

**Влияние на эталоны.** Меняются тела ровно 17 статей. Заголовки не меняются, поэтому `search-data.js`, `index.html` и сайдбары остаются прежними. После пересборки `diff -r` между старым и новым `dist/` должен показать ровно 17 HTML-файлов. Это и есть проверка коммита.

### Процедура

1. **Список.** Детектор находит управляющие символы. TAB попадает в список, только если стоит внутри формулы `$…$`/`$$…$$` вне кода (с учётом кода в выносках, где строки начинаются с `>`). Сейчас: 96 мест, 17 файлов, каждое показывается владельцу.
2. **Замена** только по этому списку: TAB → `\t`, BEL → `\a`, BS → `\b`, FF → `\f` (в `go-workout` ещё CR → `\r`, VT → `\v`).
3. **Проверки.**
   * `git diff --numstat` показывает 17 файлов.
   * `git diff --word-diff=porcelain` показывает ровно 96 замен «1 символ → 2 символа», других изменений нет.
   * В headless Firefox на этих 17 страницах 0 `.katex-error` (сейчас 9) и нет управляющих символов в тексте (сейчас на 6 страницах). Число `.katex` не уменьшилось.
4. Коммит `fix(sources): restore LaTeX escapes corrupted in editorial rewrite (U18)`.
5. Коммит `feat(audit): fail on control characters in sources/`. Правила:
   * любой символ C0, кроме `\n` и `\t`, — ошибка; DEL (`\x7F`) — тоже;
   * TAB внутри формулы вне кода — ошибка;
   * CR — ошибка с подсказкой «переведите файл на LF» (сейчас CRLF-файлов нет, но редакторы на Windows их создают).
6. `chore(dist): rebuild site`, затем чистый аудит.
7. Только после этого А0.

Те же правила аудита нужны движку (`engine/audit.py`): при миграции `go-workout` они нужны с первого дня (Н9, U25).

## 4. Q2 (U16 → U21, U22): разделы глав `go-workout`

### Сначала факт, который меняет вопрос

В критике №3 я написал: «разделы есть только у глав 1–22… у глав 23–100 разделов нет». **Это неверно.** Я искал переменную `section_groups`, а в главах 23–57 список называется `sections` с тройками `(начало, конец, название)`, в главах 58–100 — парами `(начало, название)`. U16 («каталоги разделов только в главах 1–22») владелец принимал на моих неверных данных. Я задал вопрос заново. Решение — **U21: каталоги разделов во всех 100 главах.**

### Где хранить описание раздела

Название раздела в имени каталога не помещается: 368 из 369 длиннее 50 символов (лимит из раунда 4). Значит, полное название в любом случае придётся хранить в файле. Остаётся выбрать, в каком.

| | **А: `00. О разделе.md` в каталоге раздела** | **Б: всё в `000. О главе.md`** |
|---|---|---|
| Правило в движке | одно: файл с номером из нулей (`0.`, `00.`, `000.`) — заглавная страница своего каталога на любой глубине. Глава и раздел обрабатываются одинаково | два: заглавная страница главы и разбор её текста, чтобы сопоставить абзацы с каталогами разделов |
| Название в сайдбаре | короткое имя каталога (≤ 50 символов) | то же |
| Полное название | H1 файла раздела (`title_source = "h1"`) | строка в файле главы; связь с каталогом — по номеру или тексту |
| Хлебные крошки | Глава › Раздел › Задача, все — ссылки | у раздела нет своей страницы: ссылка ведёт в никуда или на якорь в странице главы |
| Сайдбар | узел раздела — ссылка на его страницу | узел без ссылки |
| Переименовали каталог | ничего не ломается: файл лежит внутри | связь с текстом главы может молча порваться |
| Правка раздела | один каталог | два места |
| Файлов | +369 | +0 |

Решение — **U22: вариант А.** Что это значит для движка:

* **Правило индексного файла.** Ключ `book.toml`, например `index_file = "^0+\\. "`. В `go-textbook` таких файлов нет (есть `01.`–`09.`, но не `0.`/`00.`), поэтому вывод не меняется и оракул А1–А2 соблюдён.
* **Заглавная страница каталога.** Это H1 и текст файла, а под ним список дочерних страниц, который строит движок: у 288 разделов описания нет, и страница не должна быть пустой. Заглавная страница не считается задачей в счётчиках. В пагинацию «назад/вперёд» она входит, чтобы, переходя в новый раздел, читатель видел его название.
* **Б1:** `sources/NNN. Глава/000. О главе.md` (hero), `sources/NNN. Глава/NN. Раздел/00. О разделе.md`, задачи — в каталоге раздела. H1 файла раздела — исходное название без изменений. Короткое имя каталога строит инструмент Б0, список показывается владельцу.
* **Проверка полноты Б1** дополняется: 369 каталогов; H1 каждого `00. О разделе.md` побайтно равен исходному названию; 81 описание перенесено побайтно; задачи каждого каталога точно совпадают с диапазоном раздела.

## 5. Q3 (U17 → U23): страницы с расхождением после исправления списков

Число 18 — из моего прототипа в раунде 7. Скрипт не сохранился, а проекция текста там не учитывала выделение. Я написал прототип заново: `Preprocessor` с приоритетом 24. Если строка пункта идёт сразу после строки текста, он вставляет перед ней пустую строку, а вложенные пункты с отступом 2–3 пробела приводит к 4. Теперь проекция текста учитывает маркеры пунктов, номера `<ol>` и маркеры выделения. Она различается на 37 страницах, а если сначала починить ограды с отступом — на 29. Число зависит от реализации и проекции. Поэтому в плане его быть не должно, список строит инструмент коммита А3л.

### 6.3. 🟠 В22. `CodeSpanIndex`: дело не в UTF-8, а в другом тексте

**Про UTF-8.** `FENCED_BLOCK_RE.finditer` работает со строкой `str`, и `m.span()` — индексы символов Unicode, а не байтов. `_clean_cliches`, wikilinks и TOC берут позиции из той же строки. Пока никто не смешивает `str` с `bytes`, многобайтовые символы ничего не сдвигают. Это свойство Python, тест для него не нужен.

**Настоящее расхождение** в том, что индекс ищет код в сыром тексте, а Python-Markdown — в нормализованном. `NormalizeWhitespace` (приоритет 30) раньше `fenced_code`:

* заменяет CRLF и CR на LF;
* выбрасывает STX/ETX;
* раскрывает TAB (`expandtabs`).

| Вход | `CodeSpanIndex` | Python-Markdown |
|---|---|---|
| ```` ``` ```` + TAB как закрывающая ограда | ограда не закрыта | закрыта (TAB стал пробелами) |
| Файл с CRLF | ограда не закрыта (`\r` перед `$`) | закрыта |
| STX внутри закрывающей ограды | не закрыта | закрыта |

В наших корпусах таких мест 0. Но первая строка таблицы опровергает и мою критику №7 (§ 9).

Ещё два случая, где индекс видит не тот код:

* **Выноски.** Тело выноски разбирается отдельным вызовом `md.convert`. В тексте всей статьи строки кода в выноске начинаются с `> `, и `FENCED_BLOCK_RE` их не видит. После рекурсии выносок (А3а′) индекс строится **по тексту каждой единицы конвертации**: статьи и тела каждой выноски.
* **Ограды с отступом после А3з** — тоже код. Если маска их не включает, `[[…]]` внутри такого блока превратится в `<a>` до Python-Markdown и окажется видимым HTML внутри кода. Это дефект U10, только в новом месте. Сейчас в корпусе таких мест 0 (`map[[26]int]` не совпадает с `\[\[…\]\]`).

**Предложение:**

* Маска строится **по строкам** и по выходу того же конвейера препроцессоров, что и в сборке. Текст проходит `NormalizeWhitespace` (число строк он сохраняет, кроме одиночного CR), затем `FENCED_BLOCK_RE` и, если включено, тот же поиск оград с отступом, что у `IndentedFenceExtension`. Строки, попавшие в код, отмечаются. Позицию в сыром тексте переводит в номер строки `bisect` по началам строк.
* CR нормализуется при чтении файла (сейчас CRLF-файлов нет), так что строки сырого и нормализованного текста совпадают.
* Свойство-тест сравнивает маску с тем, что дал **тот же экземпляр `md`**, на корпусе и на синтетике из таблицы выше.

## 8. Новые слепые зоны

### 🟠 Н8. Markdown внутри заголовков H2–H4 не обрабатывается

`_process_headings` заменяет строку `## Заголовок` на `<h2 id="…">Заголовок</h2>` **до** Python-Markdown. Сырой HTML парсер пропускает как есть, поэтому разметка внутри заголовка не работает:

```html
<h2 id="anatomiya-struktury-testing-b">Анатомия структуры `testing.B`</h2>
```

* 1 207 заголовков на 391 странице с `` `код` ``: читатель видит обратные кавычки.
* 4 заголовка с `**жирным**`.
* `4. Linux /proc/<pid>/maps и perf`: `<pid>` браузер принимает за тег, и слово пропадает.
* TOC в порядке: `clean_title` вырезает `` ` ``, `*`, `_`.

Ни один раунд, включая мои, этого не заметил.

**Прототип.** `_process_headings` оставляет строку `## …` и собирает TOC как сейчас. `id` ставит treeprocessor в основном проходе по готовому списку якорей, тела выносок он не трогает. Результат:

* число заголовков совпадает с TOC на всех 1 413 страницах;
* `id` и TOC не меняются ни на одной странице;
* вне заголовков HTML отличается только пробелами между тегами;
* видимый текст меняется в 1 218 заголовках на 398 страницах;
* 119 заголовков с формулами не меняются.

**Решение владельца — U24:** исправить отдельным коммитом А3. Проверка:

* списки `id` и TOC равны на всех страницах;
* вне заголовков разница только в пробелах между тегами (нормализатор `verify_diff.py`), либо реализация сохраняет пробелы как сейчас;
* изменённые заголовки перечисляет инструмент;
* рантайм-проекция KaTeX в заголовках не меняется.

### 🟠 Н9. Та же порча LaTeX в данных `go-workout`

В `chapter*_data.json` 229 повреждённых команд в 106 полях (93 задачи):

* CR вместо `\r` — 99 (`\right`, `\rceil`, `\rfloor`);
* TAB — 106 (`\text`, `\times`, `\to`);
* BEL — 12, FF — 7, VT — 5 (`\varepsilon`).

Хуже всего CR: `NormalizeWhitespace` превращает его в перевод строки, и формула `\left( … \right)` рвётся пополам, а абзац может разорваться. В `section*.py` (глава 1) и `go-workout/sources/*.md` таких символов нет.

**Решение владельца — U25:** восстановить в Б1 по правилу § 3: только внутри формул, по списку, с отчётом о каждом месте. Проверка полноты Б1 должна знать эти замены, иначе «текст JSON = текст Markdown» не сойдётся на 106 полях. Аудит движка падает на любом управляющем символе в `sources/`.

### Ещё одно наблюдение для `go-workout`

Все `[[…]]` в данных `go-workout` — это данные, а не ссылки: вывод Go-программ (`[[0 0 0] [0 0 0]]`), TOML `[[runners]]`, JSON-бомбы `[[[[…]]]]`. В коде они защищены, в inline-коде их оставляет U20. Но проще и надёжнее выключить разбор wikilinks в `book.toml` задачника (`wikilinks = false`). Я бы ввёл такой флаг.
