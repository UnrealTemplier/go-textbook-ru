### 5.1. 🟠 Е1. А3е теряет `#` в конце заголовка, и оракул этого не отделяет

`sources/17. Безопасность (AppSec в Go)/05. Безопасность API/1. Валидация входных данных.md`, строка 199:

```markdown
## Сравнение подходов: Go против PHP и C#
```

Сейчас заголовок выводится сырым HTML, и читатель видит «C#». После А3е заголовок обрабатывает Python-Markdown. `HashHeaderProcessor` считает завершающие `#` закрывающей последовательностью и срезает их, даже если перед ними нет пробела (CommonMark требует пробел). Читатель увидит «…PHP и C». `id` и TOC не меняются: они считаются из сырого текста. Это потеря слова автора (U8), то есть не правка разметки, которую разрешает U24.

`verify_heading_oracle` помечает эту страницу, но среди 393 страниц, где правки санкционированы. Список «изменённые заголовки (U24)» её пропустил бы. Я тоже пропустил её в критике №13 (§ 7).

**Исправление (проверено):**

1. Перед Python-Markdown экранировать хвост из `#` в строках-заголовках вне кода: `C#` → `C\#`. Это те же строки, что попадают в TOC. Результат на корпусе: меняется ровно эта страница, видимый текст заголовков равен старому на всех 1 413 страницах, `id` равны везде. В данных `go-workout` таких заголовков 0.
2. **Оракул А3е сравнивает видимый текст, а не только разметку.** Для каждого `<h2–4>` (парсер HTML, не регулярка) должны совпасть `id` и видимый текст. Из старого текста снимаются только `` ` `` и `**`, которые U24 превращает в разметку. На корпусе это даёт 0 расхождений при исправлении п. 1 и ровно 1 без него. Список страниц с изменённой разметкой (391 + 1) строится отдельно, как и договорено. У `verify_heading_oracle` из ответа есть ещё один пробел: регулярка `<h[2-4]\b[^>]*>` отбрасывает атрибуты, и смена `id` проходит незамеченной (`verify_heading_oracle('<h2 id="a">X</h2>', '<h2 id="b">X</h2>') == True`). Проверка `id` = TOC из В27 остаётся отдельной обязательной частью оракула.

### 5.2. 🟠 Е2. Проверка `window.__BOOK__` отключает весь `main.js`

Ответ (§ 2.4 п. 2 и § 3.5):

```javascript
document.addEventListener('DOMContentLoaded', () => {
  if (!window.__BOOK__) {
    // Graceful degradation: тема и ретро-эффекты пассивно отключаются без ошибок
    return;
  }
  initTheme();
  initRetroEffects();
  // ...
});
```

Комментарий говорит «тема и ретро-эффекты», но `return` выходит из всего обработчика. Сейчас в нём 12 вызовов (`main.js:1262–1275`): `saveMermaidSources`, `initMermaid`, `initKaTeX`, `initActionDelegation` (копирование, модальное окно), сайдбар, поиск и т. д. Проверка нужна для смешанных версий: старый HTML без `window.__BOOK__` с новым `main.js`. Старый HTML подключает `assets/main.js` без `?v=` и получит новый файл. На такой странице не будет диаграмм, формул и кнопок. Получается ровно та поломка, от которой защищает проверка. Кроме того, `initTheme` и `initSidebarHydration` в коде нет: функции называются `initThemeSwitcher`, а гидрация появится только в А-фазе.

**Исправление** (решение уже записано в тексте ответа, меняется только код):

```javascript
document.addEventListener('DOMContentLoaded', function () {
  saveMermaidSources();
  initMermaid();
  // … остальные вызовы в порядке § 6 AGENTS.md …
  initGlobalSearch();
  if (window.__BOOK__) {        // старый HTML без __BOOK__: только тема и ретро-эффекты не запускаются
    initThemeSwitcher();
    initRetroEffects();
  }
});
```

Восьмой сценарий `test_runtime.py` («старый HTML без `__BOOK__`») проверяет не только отсутствие исключений, но и то, что Mermaid отрисован, KaTeX отработал, кнопка копирования работает.
